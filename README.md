# 发布工作台

一个用于演示研发协作的独立工作台：六项发布准备放在同一张任务表里，由账号 A 交代问题，账号 B 接单、提交修改，最后由 A 验收。

当前版本已修复「只看待处理」筛选：点选后只留下没做完的事，已完成的任务不再出现。并新增「生成发布清单」：在右侧列出未完成事项与截止时间、可一键复制清单。清单只在页面显示，不会自动发送消息。

## 本地打开

需要 Node.js 和 Python 3，不需要安装任何依赖。

```sh
npm run serve
```

打开 `http://127.0.0.1:5173`。搜索、状态、优先级筛选、「只看待处理」、任务状态更新和发布清单都在当前页面运行；刷新恢复六项初始数据，不连接后台服务。

点「生成发布清单」后，右侧展开窄清单面板，原任务表保持可见：

- 清单只列尚未完成的事项及各自截止时间，已完成事项不列入。
- 「复制清单」把清单文本复制到剪贴板，只复制清单，不自动发送消息。
- 六项任务全部完成时，面板显示「已经全部准备好了，可以发布」。

## 检查与复现

```sh
npm test
npm run reproduce
```

- `npm test` 检查已有的搜索、组合筛选、状态更新能力，以及发布清单的取项与复制文本逻辑，应通过。
- `npm run reproduce` 检查「只看待处理应留下五项、排除已完成项目」。教学初始版本应失败；筛选修复后应通过。
- 修复不得改写复现的预期来掩盖问题，也不得为了筛选而修改任务本身的状态。

## 协作与交付

1. A 在项目的问题单中明确 `@B` 交代本次任务。
2. B 只处理本次明确交办的内容，保持既有页面外观、其他筛选和检查。
3. B 在分支提交修改申请（Pull Request，简称 PR），用中文说明改了什么、怎样验证。
4. A 打开修改后的页面亲手验证，确认后再决定是否合并。

不自动合并，不直接改默认分支。后续功能由 A 在同一份 PR 的新留言中交办；没有明确交办前，不提前实现。
